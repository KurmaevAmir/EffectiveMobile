# Тестовое задание

## Функционал

### 1. Аутентификация и работа с пользователем
- **Регистрация**: ввод имени, фамилии, отчества, email, пароля, повтор пароля.
- **Login**: вход по email и паролю → выдача JWT-токена.
- **Logout**: добавление токена в `BlacklistedToken`, блокировка дальнейших запросов.
- **Обновление данных**: изменение профиля.
- **Удаление пользователя (мягкое)**: установка `is_active=False`.

### 2. Авторизация (разграничение прав)
- Каждому пользователю назначаются **роли**.
- Для каждой роли задаются **правила доступа** (`AccessRule`), включающие:
  - `read`,
  - `create`
  - `update`,
  - `delete`.
- При обращении к ресурсу система:
  - возвращает **401 Unauthorized**, если пользователь не аутентифицирован;
  - возвращает **403 Forbidden**, если доступ к ресурсу запрещен.

### 3. Бизнес-объекты
В системе определены условные сущности:
- `BusinessElement` – объект бизнес-логики (например, товары, заказы).
- `BusinessItem` – конкретный элемент (созданный пользователем или доступный по правилам).
- Доступ к объектам регулируется через `AccessRule`.

## Структура БД

Основные таблицы:

- `users_user` – пользователи системы.  
- `roles` – роли (админ, менеджер, пользователь).  
- `business_elements` – бизнес-объекты (например, `items`).  
- `access_rules` – правила доступа ролей к объектам.  
- `business_items` – данные бизнес-объектов (связь с владельцем).  
- `blacklisted_tokens` – токены, недействительные после logout.  

### Подробно описание
## Модели

- `User` - модель пользователя.
  - Поля:
    - `id`
    - `name`
    - `surname`
    - `patronymic`
    - `email`
    - `password`
    - `is_active`
    - `is_staff`
    - `is_superuser`
- `Role` - роли в системе:
  - Поля:
    - `id`
    - `name` 
    - `description`
- `BusinessElement` - сущности бизнес-приложения
  - Поля:
    - `id`
    - `name`
- `AccessRule` - правило доступа
  - Поля:
    - `id`
    - `role` (FK `Role`)
    - `element` (FK `BusinessElement`)
    - `boolean_flags`
      - `read`
      - `create`
      - `update`
      - `delete`
- `BusinessItem` - таблица для демонстрации бизнес-объекта
  - Поля:
    - `id`
    - `element` (FK `BusinessElement`)
    - `owner` (FK `User`)
    - `data`
    - `title`

## 📂 API

- `POST /api/v1/auth/users/` – регистрация
- `POST /api/v1/auth/jwt/create/` – вход
- `POST /api/v1/auth/logout/` – выход
- `GET /api/v1/items/` – список бизнес-объектов, доступных пользователю
- `POST /api/v1/items/` – создание бизнес-объекта (при наличии прав)
- `PUT /api/v1/items/{id}/` – обновление
- `DELETE /api/v1/items/{id}/` – удаление  
- `GET /api/v1/access-rules/` – управление правилами доступа 
(только для админов)
